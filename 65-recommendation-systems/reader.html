1. A capped candidate union and the right ranking ceiling

A capped candidate union and the right ranking ceiling

How does capping a union of candidate sources change recall, and what is the ranking ceiling for the metric you are scored on?

Candidate coverage limits what any ranker can do. Each user's list is a deduplicated union of history, co-visitation and popularity items, cut to the cap in source order. A larger union can still lose useful items if source priority pushes them past the cap.

h_u is the number of user u's true items found in the capped candidate list, T_u the number of true items for user u, and 3 the AP depth. The oracle assumes a perfect ranker puts every retrieved true item first.

Predict first. At a cap of 4, micro recall is 0.857. What is the oracle MAP@3, the best a perfect reranker could score?

With a cap of 4, the three users keep 6 of 7 true items: 6 / 7 = 0.857 micro recall. User 1 has 4 true items and 3 hits, so recall is 3 / 4 = 0.75, while the AP@3 ceiling is min(3, 3) / min(4, 3) = 1.00. Oracle MAP@3 is 1.000: recall and AP@3 use different denominators, so they need not agree.

Worked steps

  1. Cap 4: each user's deduplicated union (history, co-visitation, popularity) is cut to its first 4 items.
  2. Hits and true items per user: user 0: 1 of 1; user 1: 3 of 4; user 2: 2 of 2.
  3. Micro recall: 6 / 7 = 0.857.
  4. Macro recall: mean of 1.00, 0.75, 1.00 = 0.917.
  5. Oracle AP@3 per user: 1.00, 1.00, 1.00, mean 1.000.

Use the idea

Measure coverage on the retained candidate set, then compute the oracle ceiling with the competition's exact metric and output length. Compare candidate changes and ranker changes separately.

Where the conclusion applies

Three constructed users with binary relevance, and the AP@3 denominator is min(true items, 3). The oracle is an analytical upper bound for this exact candidate set, not a trained ranker, and source order sets which items survive truncation.

Check your understanding: At a cap of 1, which is larger: micro recall or the oracle MAP@3?
Micro recall: only user 1 has a hit, so micro recall is 1 / 7 = 0.143, while oracle MAP@3 is (0 + 0.333 + 0) / 3 = 0.111.
