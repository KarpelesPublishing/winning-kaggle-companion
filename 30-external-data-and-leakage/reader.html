Chapter 30

External Data and Leakage

Join external values by when they became available, not by event date.

External data has an event time and a release time. One demonstration varies the publication lag and compares an event-only join with a release-aware join at one prediction time.

Every example is a constructed teaching example. Its results describe the declared inputs of the chapter activity, not a measured competition gain.

1. Event time versus release time in an external join

Demonstration 1 of 1

Event time versus release time in an external join

Which external value was actually available when the prediction was made?

An external feature has an event time and a separate time when its value became available. A lookup that matches only the event date can return a value that had not yet been published. The release-aware lookup keeps only records dated and released before the prediction time.

The later record is released at 8 + 3 = 11, not before prediction time 10, so the release-aware lookup falls back to 2 while the event-only lookup still returns 7. 1 record is excluded.

Worked steps

  1. Prediction time: 10.
  2. Later record: event time 8, release time 8 + 3 = 11.
  3. Usable before 10: no.
  4. Event-only value: 7; release-aware value: 2.
  5. Records excluded: 1.

Use the idea

Record event time, publication time and revision vintage separately, then build a point-in-time join that picks only values available at each prediction time. Repeat the same rule in validation.

Where the conclusion applies

Two invented records, one event at time 4 released at 5 and one event at time 8, with prediction time 10. A dated record and a successful merge do not show the value was usable; revisions and source rules need their own checks.

Check your understanding: What is the largest publication lag at which the later value is still usable before time 10?
A lag of 1: the release time is 8 + 1 = 9, before 10. At lag 2 the release time is 10, which is not before 10.
