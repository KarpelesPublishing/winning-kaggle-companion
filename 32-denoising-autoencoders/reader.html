Denoising Autoencoders for Tabular Pretraining

See how swap noise corrupts rows while keeping every cell valid.

Swap noise preserves each column's values and perturbs the relationships between columns. One demonstration swaps cells in six rows that obey a fixed relation and measures the damage.

Swap noise keeps each cell valid and breaks the row

What happens to the relationship between features when valid cells are swapped between rows?

Swap noise replaces a cell with a value that already occurs in the same column, so each column's distribution is untouched. The corrupted row, though, can break the relationship between its features. A denoising model is trained to reconstruct the untouched rows from these corrupted inputs.

x_i1 is the first feature of row i, x~_i2 its second feature after swapping (the original is 2 * x_i1), and MSE_rel the relation error, averaged over all six rows.

2 swapped cells give squared gaps that add to 32, so 32 / 6 = 5.33. Every swapped value is still a value that occurs in column 2, but 2 rows no longer match their first feature.

Worked steps

  1. Cells swapped: 2 of 6.
  2. Each swapped cell takes the second-column value of another row, so it stays a valid column value.
  3. Squared gaps from x2 = 2 * x1, summed over the six rows: 32.
  4. Relation error: 32 / 6 = 5.33.

Use the idea

Check whether your real features share useful relationships before assuming reconstruction will help. Compare any pretrained model with random initialization and your existing tree baseline on the same folds.

Where the conclusion applies

Six rows that obey x2 = 2 * x1, and a fixed rotation of donor values rather than random swaps. This illustrates the corruption and is not DAE training; it does not show a downstream gain.

Check your understanding: With one cell swapped, why is the relation error 2.67?
Row 1 takes the value 6 where 2 * 1 = 2, a gap of 4. Then 4 * 4 = 16 and 16 / 6 = 2.67.
