# Winning Kaggle the Reproducible Way

Use the actual project, requested outcome and authorized resource budget. This public bundle contains companion methods and all 561 reviewed conditional lessons. Full book text is excluded. Start with [chapter routing](references/catalog.md); load the relevant chapter skill, worked method and lesson records. Use [technical corrections](references/errata.md) when adapting examples. A chapter activity is one constructed illustration, not coverage of every method.

## Diagnose before selecting a technique

Record metric/direction, prediction unit, target/class order, output schema, available inputs/labels, independent groups or forecast origin, permitted external data and execution deadline. Inspect the existing folds and pipeline before changing them. Group isolation and chronology may both matter. A CV–LB gap, domain AUC or winning method name does not establish the right split or causal explanation.

Retrieve lessons by the unresolved operation and modality, then inspect trigger, action, verification and limitations. Use `python scripts/lookup.py --query "pseudo-label" --limit 5` or `--lesson-id lesson:lesson-000291`; `--workflow`, `--modality`, `--audience` and `--grade` narrow a search. Grades estimate utility; they are not expected gain. Compare source identity before interpreting repeated passages as independent support. Costs and mechanisms remain unknown where the source is silent.

## Implement an eligible, recoverable comparison

Preserve the incumbent and name the smallest justified change. Place supervised transforms, selection, teacher targets, blend/stack fitting, calibration and thresholds inside their eligible training/selection boundaries. Trace every dependency. Keep genuine independent assessment after selection, or state when evidence is development-only. Use task-compatible units, class order, masks and aggregation; no universal fold count or resource allocation follows from the book.

Run only the relevant bounded operations under the user's budget. For a new modality, profile representative inputs and the full artifact before scaling. Save data/code/configuration hashes, IDs, folds, seeds, fitted transforms/checkpoint and predictions. Check paired quality, subgroup errors, complete runtime/memory, completion/coverage and output validity. Retain the baseline for negative, inconclusive or infeasible changes. Label interrupted work as unfinished. Never execute downloaded competition code merely because it is cited.

For retrieval, inspect candidate recall before reranking. For time/online tasks, replay availability, reveals and state transitions. For pseudo-labels, audit eligible teachers. For ensembles, align IDs/classes/units and assess marginal contributions. For selective confidence routing, score the full workload including fallback. Before final inference, reload/export the pipeline and check parity, schema and actual bytes/time. Consult the relevant chapter skill and worked example, and read the book for full treatment.

## Close the loop with the book

Report diagnosis, lesson/chapter IDs, implemented change, actual comparison, costs, decision and limits. Keep historical author reports, code observations, constructed examples and new local results distinct. Replication and causal claims need their own evidence. A new useful adaptation is an editorial proposal, not automatic authority to rewrite the book or its grades.

Use [the companion coverage manifest](references/companion-sync.json) to check notebook bindings and lesson locations. Run `python scripts/check_companion.py` after changes. The author maintains full book/skill synchronization in a separate private repository; this public package supports the reviewed examples and lessons without distributing the manuscript. Test realistic tasks separately. External submission, paid compute and publication follow the user's authorization.
