Which inference pipeline fits a runtime cap once model loading and throughput are both counted?

Budget model loading and per-example inference together, since a strong pipeline that exceeds the execution cap is unusable. Here loading happens once and examples run one after another, so total time is load time plus examples times seconds per example.

2.0 hours is 7200 seconds. The compact staged pipeline needs 60 x 20 + 10000 x 0.8 = 9200 seconds, leaving a margin of 7200 - 9200 = -2000 seconds. No pipeline is chosen: the ones that fit have capability below 2, and the ones with enough capability run past the allowance. These timings are planning inputs, not measured hardware speeds.

Worked steps

  1. Allowance 2.0 h x 3600 = 7200 seconds.
  2. Lightweight baseline: 60 x 10 + 10000 x 0.2 = 2600 s, margin 4600 s.
  3. Compact staged: 60 x 20 + 10000 x 0.8 = 9200 s, margin -2000 s.
  4. Larger staged: 60 x 35 + 10000 x 1.1 = 13100 s, margin -5900 s.
  5. Capability needed: 2 or more. Chosen: none.

Use the idea

Read the actual competition's runtime and hardware rules from dated official sources, profile loading and inference on representative inputs, and keep a feasible reference pipeline as a fallback.

Where the conclusion applies

All timings are hypothetical planning inputs, not Kaggle hardware benchmarks. Serial uniform throughput, a single load and no batching gain are assumed, and the capability ratings are worksheet assumptions. Verify the real rules and measure throughput before planning a submission.

Check your understanding: In half-hour steps, what is the smallest allowance at which the compact staged pipeline is chosen, and by how much does it miss at the step below?
3.0 hours: 10800 - 9200 = 1600 seconds of margin. At 2.5 hours the cap is 9000 s, so it misses by 200 s (margin -200).
