Chapter 35

Memory Optimization for Large Datasets

Count what a smaller dtype saves and what it merges.

Downcasting saves memory and can merge values that differ. One demonstration compares 32-bit and 64-bit storage on three consecutive large integers.

Memory saved versus values that stop being distinct

How much memory do you save when you halve the storage width, and which values stop being distinguishable?

Saving memory can change what a model is able to distinguish. These values are well inside the range of a 32-bit float, yet it cannot keep all three apart. Range compatibility is not precision compatibility.

At 32 bits the three values take 12 bytes, 24 - 12 = 12 fewer than at 64 bits. 3 - 2 = 1 distinct value lost, with a worst-case error of 1. The byte estimate covers the array only, not the dataframe, model buffers or temporary copies.

Worked steps

  1. Storage width: 32 bits, so 3 values need 3 * 32 / 8 = 12 bytes.
  2. Savings against 64 bits: 24 - 12 = 12 bytes.
  3. Maximum absolute conversion error: 1.
  4. Distinct values kept: 2 of 3.

Use the idea

Before downcasting a real column, name the tolerated error and check collisions as well as the minimum and maximum. Treat identifiers separately from measurements, then profile peak memory through the whole pipeline.

Where the conclusion applies

Three fixed values and one conversion rule (IEEE binary32 against 64-bit floats). The byte estimate counts the array only and excludes dataframe objects, model buffers and temporary copies.
