Nearest-Neighbor Features

1. How neighborhood size changes a local target summary

Demonstration 1 of 1

How neighborhood size changes a local target summary

How does the choice of K change the local target mean and the distance of the donors behind it?

A neighborhood feature summarizes the labels of a defined set of eligible donors near a query. Raising K averages in more rows, which smooths the summary and also admits donors that are farther away. Whether that smoothing removes noise or erases a useful boundary is a modeling question the table cannot settle.

With K = 2 the donors are rows 1, 0. 0 of the 2 carry target 1, so 0 / 2 = 0.00. Their distances add to 0.40, so 0.40 / 2 = 0.20. A larger K smooths the summary, and it also pulls in donors that are no longer close.

Worked steps

  1. Neighborhood size K = 2; the query is unlabeled and not a donor.
  2. Nearest eligible rows, closest first: 1, 0.
  3. Mean target: 0 / 2 = 0.00.
  4. Mean distance: 0.40 / 2 = 0.20.

Use the idea

Define donor eligibility before any lookup: exclude the query itself, outer validation labels and forbidden future or entity rows. Then compare a small grid of K values on identical folds.

Where the conclusion applies

One unlabeled query and five fixed training points on one numeric axis with a common scale. This shows how the summary moves with K, not that any K improves a model, and distance units matter.

Check your understanding: At K = 4, how many donors have target 1, and what is the mean target?
Two of the four, so 2 / 4 = 0.50. The mean distance at K = 4 is 0.40.
